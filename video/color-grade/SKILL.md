# 컬러 그레이드 / 룩 프롬프트 라이브러리 (Color Grade Library)

AI 이미지·영상 생성 프롬프트에 **색감(룩)** 을 입힐 때 쓰는 **프롬프트 블록 라이브러리**다. 핵심 원리는 앞서 정리한 LUT 이야기와 같다: **모델은 `.cube` 파일을 못 읽으므로, LUT의 *결과*(어떤 톤이 어떤 색으로 가는지)를 색보정 용어로 "묘사"해야 한다.** 이 스킬은 그 묘사를 미리 만들어 둔 **133종의 영어 "그레이드 블록"** 을, 골라서 프롬프트에 붙이기만 하면 되게 정리한 것이다.

이 스킬의 가치는 "이미지를 만든다"가 아니라 **"원하는 색감에 맞는 정확한 그레이드 블록을 골라 프롬프트에 끼워 넣는다"** 는 데 있다.

## 이 스킬이 하는 일 / 안 하는 일

**한다:**
- 사용자가 원하는 룩(틸앤오렌지, 빈티지 필름, 네온, 특정 필름스톡, 80s VHS, 골든아워 등)에 맞는 **그레이드 블록을 골라** 준다.
- 그 블록을 사용자의 **이미지/영상 프롬프트에 올바른 위치·순서로 끼워 넣어** 완성된 프롬프트를 만들어 준다.
- 여러 룩을 비교 제안하거나, 필름스톡+무드처럼 **블록끼리 조합**해 준다.

**안 한다 (라이브러리 전용):**
- **이미지/영상 생성 호출을 하지 않는다.** `generate_image`/`generate_video`를 부르는 건 이 스킬의 영역 밖이다. 실제 생성은 사용자가 직접 하거나 생성 스킬(예: `product-shot`)이 맡는다. 사용자가 "이 색감으로 만들어줘"라고 하면, **그레이드 블록을 입힌 최종 프롬프트를 만들어 건네주고**, 생성은 해당 생성 경로에 맡긴다(요청 시 product-shot 등으로 연결).
- 색감 외의 구도·피사체·동작 설계는 다루지 않는다(프롬프트의 색보정 블록만 책임진다).

## 두 가지 대원칙

1. **결과를 묘사한다 (연산이 아니라).** `lift/gamma/gain`, 곡선, Kelvin 숫자, `.cube` 파일명은 무의미하다. "따뜻한 앰버 하이라이트, 짓눌린 블랙, 청록 그림자" 같은 **눈에 보이는 결과**를 적는다.
2. **색보정 용어는 영어로 적는다.** 장면·동작은 한국어로 둬도 되지만, `crushed blacks`, `halation`, `Kodak Portra 400` 같은 색 용어는 영어 토큰이 훨씬 정확히 먹힌다. 그래서 모든 그레이드 블록은 영어다.

## 워크플로우

1. **룩 파악**: 사용자가 원하는 분위기/레퍼런스를 듣는다. 이름을 정확히 안 대도 된다("쓸쓸한 새벽 느낌" → 블루아워/멜랑콜릭 블루, "옛날 홈비디오" → 80s VHS/Super-8 등으로 매핑).
2. **룩 선택**: 아래 **인덱스**에서 후보를 고른다. 딱 하나가 정석이지만, 애매하면 2~3개를 제안해 고르게 한다.
3. **블록 가져오기**: 해당 룩이 있는 `references/*.md` 파일에서 그 항목의 **그레이드 블록**(영어)을 가져온다. 영상이면 **영상 추가** 토큰도 함께.
4. **프롬프트에 삽입**: 사용자의 장면 프롬프트 **맨 끝**에 그레이드 블록을 붙인다(삽입 위치는 아래). 영상이면 영상 추가 토큰을 블록 뒤에 잇는다.
5. **(필요시) 조합·조정**: 필름스톡+무드 등 두 블록을 합치거나, 강도를 낮춰 달라는 요청이면 caveat를 반영해 다듬는다.
6. **전달**: 완성된 프롬프트를 준다. 사용자가 생성까지 원하면 생성 경로(직접 또는 product-shot 등)로 넘긴다.

## 삽입 위치 — 이미지 vs 영상

블록은 이미지·영상 **공용**이다. **장면 → 동작/카메라 → (맨 끝)그레이드 블록** 순으로 둔다. 앞 토큰일수록 가중치가 높아, 색은 끝에 두어도 충분히 먹히면서 피사체를 해치지 않는다.

- **이미지 프롬프트**:
  ```
  [피사체 + 장면 + 구도/앵글]. <그레이드 블록 그대로>
  ```
- **영상 프롬프트**:
  ```
  [피사체 + 동작 + 카메라 무브 + 시간대]. <그레이드 블록 그대로> <영상 추가 토큰>
  ```
- **샷 간 색 일관성**: 텍스트만으론 완벽 매칭이 안 된다. **같은 그레이드 블록을 토씨 하나 안 바꾸고** 모든 컷/이미지에 복붙하고, 가능하면 보정된 시작 프레임을 레퍼런스 이미지로 넣고 시드를 고정한다.

## 그레이드 블록의 구조 (직접 만들거나 조합할 때)

모든 블록은 이 순서를 따른다. 새 룩을 즉석에서 만들거나 두 블록을 합칠 때도 이 골격을 유지한다:

```
{1 색온도 + color cast} ; {2 대비/톤 + 블랙(crushed/lifted) + 하이라이트 rolloff} ;
{3 채도 + 살릴/누를 hue} ; {4 필름 스톡 / 그레인 / halation (있으면)} ;
overall look — {룩 이름 + 무드 단어 2개}.
```

**조합 팁**: 보통 *필름 스톡 1개 + 무드/그레이드 1개*까지가 안정적이다. 슬롯당 한 방향만 — `high contrast` + `milky lifted`처럼 모순되는 토큰을 한 슬롯에 같이 넣으면 상쇄돼 탁해진다. 레퍼런스 룩 이름은 **딱 하나만**.

## 안 통하는 것 (사용자가 요청해도 피한다)

- **`.cube` 파일명·LUT 이름 문자열** (`apply Kodak2383.cube`) → 학습에 없어 무시·방해. 항상 결과를 말로 풀어 쓴 블록을 쓴다.
- **숫자/스코프 값** → Kelvin 숫자, `lift/gamma/gain`, `saturation 60%`, IRE, RGB 커브, hue 각도, `Rec.709/ACES/CDL`, `node/power window`. 다 노이즈.
- **로그/RAW 프로파일 단독** (`S-Log3`, `LogC`, `V-Log`) → *평평·회색 미완성 영상*을 부른다. 우리가 원하는 건 그 반대인 완성된 룩.
- **모호한 무드어 단독** (`cinematic`, `moody`, `aesthetic`, `epic`) → 정의가 안 된다. 반드시 구체적 색온도/톤/색조와 짝짓는다(블록들은 이미 그렇게 되어 있다). 시적 표현은 리터럴 색으로 번역.
- **차가운/호러/탈색 계열의 피부톤 주의** → skin이 시체톤이 되기 쉽다. 각 항목 *주의*를 반영해, 피부엔 최소한의 온기를 남기거나 배경과 분리해 지정한다.
- **틸앤오렌지·매트릭스 그린 남용** → 가장 흔해 "제네릭 예고편" 느낌. 강도를 낮추면 세련돼진다.
