# 카메라 무브 / 영상 모션 프롬프트 라이브러리 (Camera Motion Library)

AI **영상** 생성 프롬프트에 **카메라 움직임**을 입힐 때 쓰는 **프롬프트 블록 라이브러리**다. 원리는 자매 스킬 `composition`·`color-grade`와 같다: 카메라가 *어떻게 움직이는지의 결과*(밀어붙이는지·돌아가는지·따라가는지, 그리고 그 속도·이징)를 촬영 용어로 "묘사"한 **~66종의 영어 "모션 블록"** 을, 골라서 프롬프트에 끼워 넣기만 하면 되게 정리한 것이다.

이 스킬의 가치는 "영상을 만든다"가 아니라 **"원하는 카메라 무브에 맞는 정확한 모션 블록을 골라 영상 프롬프트에 끼워 넣는다"** 는 데 있다.

## 이 스킬이 하는 일 / 안 하는 일

**한다:**
- 사용자가 원하는 카메라 무브(푸시인, 오빗, 드론 상승, 달리줌, 트래킹, 핸드헬드 등)에 맞는 **모션 블록을 골라** 준다.
- 그 블록을 사용자의 **영상 프롬프트에 올바른 위치·순서로 끼워 넣어** 완성된 프롬프트를 만들어 준다.
- *구도(시작 프레임) + 모션 + 색감*처럼 **세 라이브러리를 합쳐** 완성형 영상 프롬프트를 만든다.

**안 한다 (라이브러리 전용):**
- **영상/이미지 생성 호출을 하지 않는다.** `generate_video`/`generate_image`를 부르는 건 이 스킬의 영역 밖이다. 실제 생성은 사용자가 직접 하거나 생성 경로가 맡는다. "이 무브로 만들어줘"라고 하면 **블록을 입힌 최종 프롬프트를 건네주고**, 생성은 그쪽에 맡긴다.
- **정지 이미지에는 안 쓴다.** 카메라 무브는 시간 위에서만 보인다 — 이미지 한 장엔 의미가 없다. 이미지는 `composition`(구도)·`color-grade`(색감)로.

## 두 가지 대원칙

1. **무브 + 속도·이징을 함께 묘사한다 (방향만 던지지 않는다).** `dolly in`, `orbit`, `crane up` 같은 용어는 영상 모델이 알아듣지만, **얼마나 빠르게·어떻게**(slow creeping / smooth and steady / fast snap / easing in and out)를 함께 줘야 의도대로 움직인다. 또 피사체를 어떻게 유지하는지(keeping the subject centered/in frame)를 적어 피사체가 화면 밖으로 빠지지 않게 한다.
2. **카메라·무브 용어는 영어로 적는다.** 장면·동작은 한국어로 둬도 되지만, `slow push-in`, `360-degree orbit`, `whip pan`, `dolly zoom`, `speed ramp` 같은 무브 용어는 영어 토큰이 훨씬 정확히 먹힌다. 그래서 모든 모션 블록은 영어다.

## 삽입 위치 — 구도·색감과 한 줄로 합쳐진다

영상 프롬프트는 **구도(시작 프레임) → 피사체·동작 → 모션 → 색감** 순으로 쌓는다. 구도가 첫 프레임을 정하고, 모션이 그 프레임을 시간 위에서 움직이고, 색감이 룩을 입힌다:

```
<composition 구도 블록> [피사체 + 동작 + 시간대]. <camera-motion 모션 블록> <(선택)color-grade 그레이드 블록>
```

- 모션 블록은 **피사체·동작 묘사 뒤**(움직임은 무엇을 찍는지가 정해진 다음에 와야 자연스럽다)에, 색감 블록 **앞**에 둔다.
- `composition`의 각 항목에는 그 구도에 맞는 짧은 **"영상 추가"** 토큰이 이미 있다. 가벼운 한 줄이면 그걸로 충분하고, 무브가 핵심이면 이 스킬의 **모션 블록**(더 구체적)으로 대체·강화한다.
- **샷 간 일관성**: 같은 모션 블록을 토씨 하나 안 바꾸고 모든 컷에 복붙하고, 시작 프레임을 레퍼런스 이미지로 넣고 시드를 고정한다.

## 모션 블록의 구조 (직접 만들거나 조합할 때)

모든 블록은 이 순서를 따른다. 새 무브를 즉석에서 만들거나 두 블록을 합칠 때도 이 골격을 유지한다:

```
{1 무브 종류 + 방향 — push in / orbit / crane up / track alongside} ;
{2 속도 + 이징 — slow creeping / smooth steady / fast snap, easing in/out} ;
{3 피사체·프레임 처리 — keeping the subject centered / revealing the wider scene / background compressing} ;
{4 (선택) 질감 — subtle handheld breathing / locked and stable / motion blur on the swish}.
```

**조합 팁**: AI 영상 모델은 **한 컷에 하나의 지배적 무브**를 가장 잘 소화한다. 두 개까지(예: push-in + slight orbit)는 되지만, 셋 이상 섞으면 움직임이 뭉개지거나 모델이 무시한다. 모순 무브(zoom in + dolly out)는 의도된 *dolly zoom*이 아니라면 같이 넣지 말 것. 속도는 한 방향으로 — `slow` + `fast snap`을 한 슬롯에 같이 쓰지 않는다.

## 워크플로

1. **무브 파악**: 사용자가 원하는 느낌/레퍼런스를 듣는다. 이름을 정확히 안 대도 된다("긴장감 있게 다가가" → slow creeping push-in, "제품 빙 돌려서" → orbit, "현장감 있게" → handheld/steadicam follow, "갑자기 확 당겨" → crash zoom, "공간 보여주면서 빠져" → crane-up reveal 등으로 매핑).
2. **무브 선택**: 아래 **인덱스**에서 후보를 고른다. 딱 하나가 정석이면 그걸로, 애매하면 2~3개를 제안해 고르게 한다.
3. **블록 가져오기**: 해당 무브가 있는 `references/*.md`에서 그 항목의 **모션 블록**(영어)을 가져온다. 어울리는 시작 구도는 **페어링** 참고.
4. **프롬프트에 삽입**: 피사체·동작 묘사 뒤, 색감 앞에 모션 블록을 붙인다. 구도까지 원하면 `composition` 블록을 맨 앞에 둔다.
5. **(필요시) 조합·조정**: "더 천천히 / 더 빠르게 / 피사체 고정해서" 요청을 속도·이징·피사체 처리에 반영해 다듬는다.
6. **전달**: 완성된 영상 프롬프트를 준다. 생성은 사용자/생성 경로에 맡긴다.

## 안 통하는 것 (사용자가 요청해도 피한다)

- **한 컷에 무브 과적재** → `dolly in + orbit + crane up + pan`을 한꺼번에 넣으면 AI 영상이 뭉개지거나 무시된다. 지배적 무브 1개(많아야 2개)만.
- **속도·이징 없는 방향만** (`dolly in`만) → 약하다. 항상 *얼마나 빠르게·어떻게*(slow, smooth, easing, fast snap)를 함께.
- **모순 무브 동시 지정** → `zoom in` + `dolly out`은 의도한 *dolly zoom*이 아니면 상쇄된다. 반대 방향 무브를 무심코 합치지 말 것.
- **피사체 처리 누락** → 빠른 무브에서 피사체를 어떻게 유지할지 안 적으면 화면 밖으로 빠진다. `keeping the subject centered/in frame`을 명시.
- **정지 이미지에 모션 블록** → 의미 없음. 이미지엔 `composition`·`color-grade`만.
- **극단적 속도/복잡 궤적** (초고속 크래시 줌 + 360 + 셰이크) → 짧은 클립에서 모델이 못 따라가 아티팩트. 클립 길이에 맞는 무브 1개로 절제.
