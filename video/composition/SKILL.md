# 구도 / 프레이밍 프롬프트 라이브러리 (Composition Library)

AI 이미지·영상 생성 프롬프트에 **구도(프레이밍·앵글·렌즈 원근)** 를 입힐 때 쓰는 **프롬프트 블록 라이브러리**다. 원리는 자매 스킬 `color-grade`와 같다: color-grade가 *LUT의 결과*(어떤 톤이 어떤 색으로 가는지)를 색보정 용어로 "묘사"하듯, 이 스킬은 *프레이밍 선택의 결과*(피사체가 화면에서 얼마나 차지하는지, 카메라가 어디 있는지, 무엇이 선명하고 무엇이 흐린지)를 카메라 용어로 "묘사"한 **94종의 영어 "컴포지션 블록"** 을, 골라서 프롬프트에 끼워 넣기만 하면 되게 정리한 것이다.

이 스킬의 가치는 "이미지를 만든다"가 아니라 **"원하는 구도에 맞는 정확한 컴포지션 블록을 골라 프롬프트의 *맨 앞*에 끼워 넣는다"** 는 데 있다.

## 이 스킬이 하는 일 / 안 하는 일

**한다:**
- 사용자가 원하는 구도(로우앵글, 삼분할, 와이드 establishing, 망원 압축, 버즈아이, 프레임 인 프레임 등)에 맞는 **컴포지션 블록을 골라** 준다.
- 그 블록을 사용자의 **이미지/영상 프롬프트에 올바른 위치·순서로 끼워 넣어** 완성된 프롬프트를 만들어 준다.
- 여러 구도를 비교 제안하거나, *샷 사이즈 + 앵글 + 구성원리 + 렌즈*처럼 **블록끼리 조합**해 준다.
- 요청 시 `color-grade`(색감)와 **합쳐** 완성형 프롬프트를 만든다 — 구도는 앞, 컬러는 끝.

**안 한다 (라이브러리 전용):**
- **이미지/영상 생성 호출을 하지 않는다.** `generate_image`/`generate_video`를 부르는 건 이 스킬의 영역 밖이다. 실제 생성은 사용자가 직접 하거나 생성 스킬(예: `product-shot`)이 맡는다. "이 구도로 만들어줘"라고 하면 **블록을 입힌 최종 프롬프트를 건네주고**, 생성은 해당 경로에 맡긴다.
- 색감·피사체 설계·동작 서사는 다루지 않는다(프롬프트의 구도 블록만 책임진다). 색은 `color-grade`로.

## 두 가지 대원칙

1. **결과를 기하학으로 묘사한다 (이름만 던지지 않는다).** `rule of thirds`, `low angle`, `85mm`, `shallow DOF` 같은 용어는 모델이 알아듣지만, **용어 + 결과의 공간 묘사**를 함께 줘야 안정적으로 재현된다. "rule of thirds"만 쓰지 말고 *"subject placed on the left third line, gaze leading into the open right two-thirds"* 처럼 **피사체가 화면 어디에 얼마나 놓이는지**를 적는다. 모델은 이름보다 공간 묘사를 더 정확히 그린다.
2. **카메라·렌즈 용어는 영어로 적는다.** 장면·동작은 한국어로 둬도 되지만, `low-angle hero shot`, `telephoto compression`, `frame-within-a-frame`, `creamy bokeh` 같은 구도 용어는 영어 토큰이 훨씬 정확히 먹힌다. 그래서 모든 컴포지션 블록은 영어다.

## 삽입 위치 — color-grade와 정반대다 (중요)

컬러 블록은 가중치를 낮추려 프롬프트 **맨 끝**에 둔다. 구도는 반대다 — **화면의 기하학을 결정하므로 가중치 높은 맨 앞**(피사체와 함께)에 둔다. 그래서 두 스킬은 자연스럽게 겹친다:

- **이미지 프롬프트**:
  ```
  <컴포지션 블록> [피사체 + 장면 디테일]. <(선택)color-grade 그레이드 블록>
  ```
- **영상 프롬프트**:
  ```
  <컴포지션 블록> [피사체 + 동작 + 시간대]. <영상 추가 카메라 무브> <(선택)그레이드 블록 + 영상 추가>
  ```

블록은 이미지·영상 **공용**이다. 영상은 블록을 그대로 쓰고 *영상 추가*(카메라 무브 토큰)를 덧붙인다. 정적 프레이밍(블록) + 그 프레이밍에 맞는 카메라 이동(영상 추가)이 한 쌍이다.

- **샷 간 구도 일관성**: 같은 컴포지션 블록을 토씨 하나 안 바꾸고 모든 컷/이미지에 복붙하고, 가능하면 시작 프레임을 레퍼런스로 넣고 시드를 고정한다.
- **aspect_ratio와 맞춘다**: 프레임 비율은 생성기의 `aspect_ratio` 파라미터가 정한다. 블록의 framing이 비율과 싸우지 않게 한다 — 9:16 세로 프레임에 "vast cinematic widescreen vista"를 넣지 말 것(대신 21:9·16:9). 세로엔 수직 레이어·풀샷, 가로엔 와이드·파노라마가 맞는다.

## 컴포지션 블록의 구조 (직접 만들거나 조합할 때)

모든 블록은 이 순서를 따른다. 새 구도를 즉석에서 만들거나 두 블록을 합칠 때도 이 골격을 유지한다:

```
{1 shot size — 피사체가 프레임을 얼마나 채우는지} ; {2 camera angle + height — eye/low/high/overhead/Dutch} ;
{3 subject placement + balance — thirds / centered symmetry / negative space / lead room} ;
{4 depth + lens/DOF — foreground·midground·background 레이어, wide 왜곡 / telephoto 압축, shallow bokeh / deep focus} ;
overall framing — {구도 이름 + 의도 단어 2개}.
```

**조합 팁**: 보통 *샷 사이즈 1 + 앵글 1 + 구성원리 1 + 렌즈/심도 1* 까지가 안정적이다. 슬롯당 한 방향만 — `centered symmetry` + `subject on the left third`처럼 모순된 배치를 한 슬롯에 같이 넣으면 상쇄돼 구도가 무너진다. 구성원리(삼분할 vs 중앙 대칭 등)는 **딱 하나만** 지배적으로.

## 워크플로우

1. **구도 파악**: 사용자가 원하는 느낌/레퍼런스를 듣는다. 이름을 정확히 안 대도 된다("위압감 있게" → 로우앵글 히어로샷, "작고 외롭게" → 하이앵글 + 넓은 네거티브 스페이스, "옛날 영화 같은 와이드" → 아나모픽 + establishing 등으로 매핑).
2. **구도 선택**: 아래 **인덱스**에서 후보를 고른다. 딱 하나가 정석이면 그걸로, 애매하면 2~3개를 제안해 고르게 한다.
3. **블록 가져오기**: 해당 구도가 있는 `references/*.md`에서 그 항목의 **컴포지션 블록**(영어)을 가져온다. 영상이면 **영상 추가**(카메라 무브)도 함께.
4. **프롬프트에 삽입**: 사용자의 장면 프롬프트 **맨 앞**에 컴포지션 블록을 붙인다. 컬러까지 원하면 `color-grade` 블록을 **맨 끝**에 잇는다.
5. **(필요시) 조합·조정**: 샷+앵글+원리+렌즈를 합치거나, "더 압축해/더 넓게/심도 더 얕게" 요청을 caveat 반영해 다듬는다.
6. **전달**: 완성된 프롬프트를 준다. 생성까지 원하면 생성 경로(직접 또는 product-shot 등)로 넘긴다.

## 안 통하는 것 (사용자가 요청해도 피한다)

- **모순된 framing을 한 번에** → `extreme wide shot` + `extreme close-up`, `centered symmetry` + `subject on the far-left third`처럼 충돌하는 토큰은 서로 상쇄돼 어중간한 컷이 된다. 지배적 구도는 하나만.
- **구성원리 과적재** → 삼분할·황금비·리딩 라인·대칭을 한꺼번에 다 넣으면 아무것도 안 먹힌다. 주된 원리 1개 + 보조 1개까지.
- **초점거리 숫자 단독** (`shot on 135mm`) → 숫자만으론 약하다. 항상 *효과*(telephoto compression, flattened background, shallow bokeh)를 함께 묘사.
- **비율과 싸우는 framing** → `aspect_ratio`와 안 맞는 framing(세로 9:16에 panoramic vista)은 잘리거나 무시된다. 블록을 비율에 맞춰 고른다.
- **물리적으로 불가능한 카메라/렌즈 조합**, **감독 이름 단독** (`shot like Kubrick`만) → 반드시 구체적 framing과 짝짓는다(블록들은 이미 그렇게 되어 있다).
- **클로즈업에서 과한 와이드 왜곡** → 얼굴이 부풀어 우스워진다(큰 코, 굽은 윤곽); 인물 클로즈업엔 85mm 압축 계열을 쓴다.
