# 브리핑 조립

워커 에이전트는 대개 Claude Code가 아니다. `.claude/skills/`도, `CLAUDE.md`도 읽지
못한다. 대상 저장소가 독립 git root라면 상위 디렉토리의 `AGENTS.md`조차 보이지 않는다.

**즉 워커는 아무 맥락 없이 시작한다.** 필요한 것을 전부 프롬프트에 넣어야 한다.

## 원칙

- 스킬 파일 전문을 붙여넣지 마라. 토큰만 먹고 워커가 핵심을 놓친다
- 추리는 기준: 워커가 이 작업을 하는 데 **모르면 틀리는 것**만
- 확실하지 않은 것을 지어내지 마라. 모르면 "확인 후 진행하라"고 쓴다
- 브리핑은 20~40줄이 적당하다. 넘어가면 무엇을 뺄지 다시 본다

## 템플릿

```
[대상]
작업 경로: <절대경로>
이 경로 밖의 파일은 읽지도 수정하지도 마라.

[스택]
<언어/프레임워크/버전 — 스킬에서 추린 한두 줄>

[알아야 할 것]
<이 저장소 고유의 함정, 명령, 규칙 — 스킬에서 3~5개만>

[하지 말 것]
- 커밋하지 마라. 변경만 남기고 보고해라
- 작업 경로 밖을 수정하지 마라
- 다른 에이전트를 스폰하지 마라. 배정된 작업만 직접 수행해라
- <프로젝트 rules.md에서 추가>

[작업]
<사용자 요청을 이 대상에 맞게 구체화. "무엇을"이 아니라 "무엇을 어디서 어떻게 확인하며">

[완료 시]
<SKILL.md의 결과 회수 계약을 그대로>
```

## 결과 경로는 반드시 작업 경로 안이다

회수 계약이 가리키는 파일은 `<작업 경로>/.claude/tmp/orchestrator/<run_id>/<이름>.md`
여야 한다. 오케스트레이터의 프로젝트 디렉토리로 쓰게 하면 안 된다.

이유는 두 겹이다. codex는 `-s workspace-write`로 뜨므로 cwd 밖 쓰기가 샌드박스에
막히고, 위 템플릿이 "이 경로 밖의 파일은 읽지도 수정하지도 마라"라고 이미 금지해 놓았다.
워커가 승인을 요청해도 SKILL.md §4의 표가 범위 밖 접근으로 보고 거부한다.
**즉 계약을 지키는 유일한 방법이 규칙 위반이 되는 데드락이 생긴다.**

경로가 작업 경로 안이면 이 문제가 통째로 사라지고, `--add-dir` 같은 예외 플래그도
필요 없어진다. 여러 레포에 흩어진 결과는 오케스트레이터가 `collect.sh`로 모은다.

계약 문구에 "이 경로는 네 작업 경로 안이므로 써도 되는 곳이다"를 남겨 두면
워커가 스스로 자기 검열해서 멈추는 것도 막을 수 있다.

## 추릴 때 보는 곳

대상 스킬 파일에서 이 순서로 찾는다:

1. `## 작업 경로` — 절대경로. 그대로 쓴다
2. description 첫 문장 — 스택과 역할이 압축돼 있다
3. `⚠️` / `주의` / `금지` 가 붙은 줄 — 우선 포함
4. 자주 쓰는 명령 (빌드, 테스트, 마이그레이션) — 워커가 검증에 쓸 것만
5. 다른 스킬과의 경계 ("~는 별개 레포이므로 혼동하지 말 것") — 범위 이탈을 막는다

## 최소 브리핑 (레지스트리에 없는 대상 / 범용 모드)

레지스트리 자체가 없는 범용 모드이거나, 레지스트리에 없는 대상을 경고 후 진행하기로
승인받았다면 이걸 쓴다:

```
[대상]
작업 경로: <절대경로>
이 경로 밖의 파일은 읽지도 수정하지도 마라.

[알아야 할 것]
이 저장소에 대한 정리된 지침이 없다. 작업 전에 README, package.json/composer.json 등
매니페스트, 기존 코드 스타일을 먼저 확인하고 그것을 따라라. 확신이 없으면 추측해서
바꾸지 말고 "확인 필요"에 적어라.

[하지 말 것]
- 커밋하지 마라
- 작업 경로 밖을 수정하지 마라
- 새 의존성을 추가하지 마라

[작업]
...
```

지침 없이 위임했다는 사실을 최종 보고에 남긴다. 그게 스킬(또는 레지스트리 항목)을
만들 후보 목록이 된다. 단, 범용 모드에서는 모든 대상이 여기 해당하므로 대상마다
반복해서 경고하지 말고 보고에 한 번만 적는다.

## 워커 kind 고르기

| 상황 | kind |
|---|---|
| 프로젝트 기본값이 registry.md에 있음 | 그것 |
| 사용자가 지정 | 그것 |
| 교차 검증 (같은 작업 다른 시각) | 오케스트레이터와 **다른** 벤더 |
| 불명확 | 사용자에게 묻는다. 임의로 고르지 않는다 |

`herdr agent`를 실행하면 설치된 kind 목록이 나온다. 목록에 없는 kind로 스폰하지 마라.
